# Visual Studio 2026 バージョン 18.7.0 リリースノート

**2026 年 6 月 9 日**リリース。

### IDE

**編集テーマの色 📣**

> _テーマの色を簡単に編集して、Visual Studioエクスペリエンスをカスタマイズできるようになりました。 エディター、ツール ウィンドウなどの色を好みに合わせて変更します。_
> 
> Visual Studioには、IDE で Fluent カラー トークンを直接カスタマイズできる新しい **Theme colors** オプション ページが追加されました。拡張機能は必要ありません。 カスタマイズはテーマごとに保存されるため、各テーマは独自の調整セットを保持します。
> 
> ![テーマの色エディター](media/18.7/theme-color-editor.png)
> 
> ##### 実行可能事項
> 
> -   アクセントカラー、ホバー状態、シェルクロムなど、**その場で Fluent トークンを調整します**。 目的のトークンを検索し、新しい色を選択します。
> -   **色ごとのリセット** - 他のすべてのカスタマイズをワイプせずに、個々のトークンを元に戻します。
> -   **どのテーマでもカスタマイズ可能** - 上書き設定は、選択したテーマの上に重ねて適用されます。
> -   **シェルとタブ/ウィンドウヘッダーの分離のための新しいトークン** - シェルヘッダーとタブヘッダーを異なる色にすることができます(よりレトロな外観が必要な場合は便利です)。
> 
> ##### アクセス方法
> 
> 新しい \[ **テーマの色の編集\]** メニュー コマンドを使用するか、設定 **で \[環境→ Visual Experience →テーマの色** \] ページを開きます。
> 
> 📣 _フィードバックを共有し、会話を続けるには、[フィーチャーチケット](https://developercommunity.visualstudio.com/t/Bring-Blue-theme-back-for-Visual-Studio-/10963534)をご覧ください_  

### 生産性

**Color emojis**

> Visual Studio IDE 全体で絵文字がフル カラーで表示され、コード コメント、マークダウン ファイル、チャット会話がより表現力豊かになりました <>
> 
> Visual Studio では、IDE 全体で絵文字がフル カラーでレンダリングされるようになりました。 役立つ視覚的な合図を使用してコードを文書化する場合でも、チャットで共同作業を行う場合でも、絵文字がモノクロのアウトラインではなく、フルカラーかつ詳細に表示されるようになりました。
> 
> ##### カラー絵文字が表示される場所
> 
> カラー絵文字は、以下で使用できます。
> 
> -   **コード コメント** - 視覚的なマーカーを、TODO 項目、警告、またはセクション ヘッダーに追加します
> -   **マークダウン ファイル** - 豊富な絵文字サポートを使用してマークダウン ドキュメントをプレビューおよび編集します
> -   **GitHub Copilot チャット** - チャットの応答や質問でカラフルな絵文字を表示します
> -   **出力ウィンドウ** - ビルド出力とログに絵文字がカラーで表示されるようになりました
> -   **ソリューション エクスプローラー** - ファイル名やプロジェクト項目内の絵文字がカラーでレンダリングされるようになりました
> 
> ![カラー 絵文字](media/18.7/color-emojis.png)
> 
> ##### 共同作業の重要性
> 
> カラー絵文字を使用すると、コードを簡単にスキャンし、重要なセクションをすばやく識別することができます。 コメント内の赤い ❌ は灰色のアウトラインよりも目立ち、緑色の ✅ はわかりやすい視覚的フィードバックを提供します。 この小さな変更により読みやすさが向上します。特に視覚的なマーカーが迅速なナビゲーションに役立つ大規模なコードベースで効果を発揮します。
> 
> レンダリングでは、最新のフォント テクノロジを使用して、さまざまな Windows バージョン間で絵文字を一貫して表示するため、自分が見ている内容とチームメイトが見ている内容は一致します。

**離れた位置にある次の編集候補**

> GitHub Copilotは、cursor.
> 
> GitHub Copilotの「次の編集提案(NES)」機能は、カーソルの位置にコードを挿入するだけでなく、その周辺の編集箇所を提案し、次に変更しようとしている内容を予測することで、Copilot の補完機能を拡張します。 補完機能にとって素晴らしい追加要素ですが、現在の位置周辺の狭い範囲に限定されていました。 実際、編集が必要な箇所は、ファイル内のかなり離れた場所にあることがよくあります。
> 
> これで、Copilot は長距離次編集候補により、ファイル内のどこでも編集候補を提案できるようになりました。 Copilot は、カーソルの周辺の変更だけに限定されるのではなく、ファイル全体にわたる編集内容を予測して提案するため、一貫性を保ち、離れた場所にある関連する変更もスムーズに行うことができます。
> 
> ![カーソル位置から離れた場所にある編集候補を示す、長距離の次の編集候補](media/18.7/long-distance-edit.png)
> 
> 遠距離の提案に関する提案の背景についての詳細情報は、モデルのトレーニングと評価について詳しく解説した[ブログ記事](https://code.visualstudio.com/blogs/2026/02/26/long-distance-nes)をご参照ください。 この機能は現在、デフォルトで無効になっています。 試すには、\[ **ツール\] → \[オプション\] → \[テキスト エディター\] → \[インライン候補** \] に移動し **、\[拡張範囲の候補を有効にする\]** をオンにします。 ぜひお試しいただき、フィードバックをお寄せください。  

**MCP サーバーの信頼の検証**

> _MCP サーバーの構成と資産に対する変更を検出し、実行前に再承認を求めます。_
> 
> MCP サーバーはCopilotの機能を拡張しますが、セキュリティで保護された状態を維持することが重要です。 Visual Studio MCP サーバーの信頼検証が含まれるようになりました。これは、サーバーの構成または資産が最後に承認されてから変更されたことを検出し、続行する前に再承認を求めるセキュリティ層です。
> 
> ##### 動作方法
> 
> 信頼は、サーバーの起動時に次の 2 つの時点で検証されます。
> 
> 1.  **構成の信頼** - サーバー プロセスが開始される前に、現在のサーバー構成が以前に信頼されたベースラインと比較されます。 構成が変更された場合は、信頼ダイアログでメッセージが表示されます。
> 2.  **資産の信頼** - サーバーが起動し、その資産 (ツール、プロンプト、リソース、命令) が読み込まれた後、そのフィンガープリントは最後に信頼されたフィンガープリントと比較されます。 資産が変更された場合、信頼ダイアログには、古いバージョンと新しいバージョンの間で分岐した内容が表示されます。
> 
> ![ユーザーに変更の確認を求める MCP 信頼ダイアログ](media/18.7/mcp-trust-dialog.png)
> 
> ##### 信頼の判断
> 
> メッセージが表示されたら、次のことができます。
> 
> -   **変更を受け入れる** - 信頼を 1 回行い、将来の比較のためにベースラインを更新します。
> -   **常に信頼** - このサーバーに対して再度プロンプトが表示されることはありません。
> -   **変更を拒否する** - サーバーの起動を中止し、信頼拒否状態のままにします。 信頼は、次回のアクティブ化の試行時に再検証されます。
> 
> 初めて接続するサーバーは、最初のアクティブ化時に暗黙的に信頼され、ダイアログは表示されません。 現在の構成と資産のフィンガープリントは、将来の変更検出の初期ベースラインとして保存されます。
> 
> また、サーバーが組み込まれている場合、MCP レジストリ ポリシーが **RegistryOnly に** 設定されている場合 (つまり、組織のポリシーによって事前に承認されている)、そのサーバーに対して以前に "常に信頼" を選択した場合、またはこの機能をオフにすると、信頼の検証も自動的にスキップされます。
> 
> この機能は、既定で有効になっています。 更新された MCP サーバーからツールを実行する前に、Tools → オプション→ GitHub → Copilot → Copilot Chat →信頼ダイアログを表示<>で管理できます。

**C++ 向け GitHub Copilot モダナイゼーション エージェント**

> 
> [GitHub Copilotモダン化エージェント](https://aka.ms/AppModCppDocs)は、アプリケーションの最新化とアップグレードに役立つ、Visual Studioの AI を利用したツールです。 Microsoft C++ (MSVC) ビルド ツールの最新バージョンを使用するようにプロジェクトをアップグレードするのに役立つ最初の C++ 固有のシナリオがパブリック プレビューを完了し、一般公開されたことをお知らせします。
> 
> 最新の MSVC バージョンを最新の状態に維持すると、新機能、パフォーマンスの向上、およびセキュリティ更新プログラムにアクセスできます。 C++ 用のモダン化エージェントは、プロジェクトを分析し、互換性の問題を特定し、最新の MSVC バージョンへのスムーズな移行を確実にするために明確なアップグレード計画を実行することで、このプロセスを簡略化します。 自動モードで実行して手動作業を減らしたり、ガイド付きモードで評価、計画、実行の手順を確認および承認したりできます。
> 
> ##### 始め方
> 
> 1.  Visual Studioで、MSVC でコンパイルする C++ プロジェクトを開きます。
> 2.  次のいずれかの方法を使用して最新化エージェントを起動します。
>     -   ソリューション エクスプローラーでソリューションまたはプロジェクトを右クリックし、Modernize、or
>     -   **Copilot Chat** ウィンドウを開き、「`@Modernize`」と入力し、アップグレード要求を続けます。
> 3.  最新バージョンの MSVC にアップグレードすることを `@Modernize` エージェントに通知します。
> 
> ![GitHub Copilot のモダナイゼーション エージェントを搭載した Visual Studio が、10 年前の C++ サンプル コードをアクティブにアップグレード](media/18.7/app-mod-msvc-upgrade-hilo-sample.png)
> 
> パブリック プレビュー期間中に C++ プロジェクトGitHub Copilot最新化エージェントを評価した多くのユーザーに感謝します。 お客様からのフィードバックは、エクスペリエンスの向上に役立ち、今後も C++ の最新化シナリオをサポートするために、この基盤を構築し続けることを楽しみにしております。 [Developer Community](https://developercommunity.visualstudio.com/cpp)で提案やフィードバックを共有することで、次に何を見たいと思うかをお知らせください。  

**C++ プロジェクト向けの NuGet PackageReference サポート 📣**

> C++ .vcxproj プロジェクトでは、コマンド ラインと Visual Studio IDE.
> 
> Visual Studio C++ プロジェクト (.vcxproj) で NuGet PackageReference がサポートされるようになりました。 現在、この機能は試験段階であり、既定ではオフになっています。
> 
> C++ プロジェクトでこの機能を有効にするには、 `EnableNativePackageReferenceSupport` プロパティをプロジェクトの Globals プロパティ グループまたは Directory.Build.props ファイルに `true` するように設定します。 その後、.NET プロジェクトの場合と同様に、`PackageReference` 依存関係を追加できます。
> 
> PackageReference を使用すると、NuGet パッケージをプロジェクト ファイル内で直接参照し、それらを自動的に復元してビルドに含めることができます。 これは、以前の packages.config アプローチと比較して、依存関係を管理するための最新の方法です。 PackageReference の詳細については、 [PackageReference に関する NuGet ドキュメント](/nuget/consume-packages/package-references-in-project-files) と [、packages.config から PackageReference への移行に関するドキュメントを](/nuget/consume-packages/migrate-packages-config-to-package-reference)参照してください。
> 
> この機能は、最新の.NET バージョンを対象とする [C++/CLI プロジェクト](https://devblogs.microsoft.com/cppblog/announcing-nuget-packagereference-support-for-c-cli-msbuild-projects-targeting-net-core/)に追加された既存のサポートに基づいています。
> 
> スコープと互換性:
> 
> -   サポート対象: .NET Core または .NET 5 以降を対象とするネイティブ C++ プロジェクト (.vcxproj) および C++/CLI プロジェクト。
> -   サポートされていません:.NET Framework を対象とする C++/CLI プロジェクト。 これらのプロジェクトでは、NuGet の依存関係に対して引き続き古い packages.config アプローチを使用できます。
> -   サポートされていません:C++/CLI プロジェクトまたは C# プロジェクトを参照する C++ プロジェクト。 このシナリオのサポートは、今後の更新プログラムで調査中です。 それまでは、次のいずれかの回避策を使用して PackageReference を動作させることができます。
>     -   `<ReferenceOutputAssembly>false</ReferenceOutputAssembly>`項目に`<SkipGetTargetFrameworkProperties>true</SkipGetTargetFrameworkProperties>`と`<ProjectReference>`を設定すると、NuGet はそれを無視でき、復元とビルドの問題は発生しません。
