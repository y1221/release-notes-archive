# Visual Studio 2026 バージョン 18.8.0 リリースノート

**2026 年 7 月 14 日**リリース。

### GitHub Copilot

**組み込みの.NETとAzureのスキル**

> _Visual Studioの組み込みの.NETとAzureスキルを見つけて、エージェント ワークフローをカスタマイズします。_
> 
> Visual Studio には、.NET と Azure チームのエキスパートが作成した組み込み機能が搭載されているため、エージェント型ワークフローをより適切にカスタマイズし、開発タスクをより効率的に完了できるようになりました。 これらの機能は、対応する .NET と Azure ワークロードがインストールされている場合に利用可能です。
> 
> これらのスキルは、ツール ピッカーの「搭載」カテゴリにあります。 各スキルにカーソルを合わせると、その説明と経路が表示されます。また、3 つのドットのメニューから、スキルの詳細を開いたり、フォルダの場所を開いたりすることができます。
> 
> ![ツール選択ツールの組み込み .NET および Azure スキル](media/18.8/inbox-skills.png)
> 
> 現在、搭載されたスキルはデフォルトで無効になっているため、自分のタスクに適したものだけを確認して有効にできます。 これにより、作業している場所に直接、ガイド付きのその分野に特化した支援を制御された方法で表示できます。 また、[.NET スキル](https://github.com/dotnet/skills) と [Azure スキル](https://github.com/microsoft/azure-skills) についてもリンクから詳細にアクセスできます。  

**Copilot の使用状況追跡とアラート**

> _リアルタイムで使用状況を追跡し、制限に近づくとアラートを受け取ることで、Copilot の使用状況を常に把握できます。_
> 
> GitHub Copilot は最近、従量課金制に移行したため、Copilot の利用量は要求数ではなく、トークンの消費量に基づいて計算されるようになりました (詳細については、[GitHub のブログ](https://github.blog/news-insights/company-news/github-copilot-is-moving-to-usage-based-billing/)をご参照ください)。
> 
> Visual Studioでのご利用を最大限に活用していただけるよう、製品の機能改善を継続的に行っており、Copilot の利用状況の最適化と追跡ができるよう努めています。 この継続的な取り組みの一環として、「Copilot の使用状況」ウィンドウを更新し、利用制限に近づいた際に事前に通知する機能を追加しました。
> 
> ##### 新着情報
> 
> Visual Studio の「Copilot 使用状況」ウィンドウを更新し、新しい課金モデルに基づいた現在の使用状況がより明確に把握できるようになりました。これにより、開発ワークフロー全体を通じて Copilot をどの程度利用しているかを簡単に追跡できるようになります。 利用状況の指標がリアルタイムで更新されるため、利用パターンを把握し、それに応じて計画を立てることができます。
> 
> **Copilot バッジ メニュー** → **Copilot Usage** からいつでも使用状況ウィンドウにアクセスします。
> 
> ![Copilot使用状況ウィンドウに現在の使用状況メトリックが表示されます](media/18.8/copilot-usage-window.png)
> 
> また、Visual Studio では使用状況について事前に通知されるため、制限に達する前に使用状況を調整できるようになります。
> 
> アラートは、次の場合に表示されます。
> 
> -   利用制限に近づいている
> -   利用制限に達している
> -   利用制限に達した後、追加利用 (オーバー チャージとも呼ばれます) が有効になります
> 
> 設定でクオータ警告のしきい値 (パーセンテージ) を調整することで、使用量の上限に近づいた際の通知が表示されるタイミングをカスタマイズでき、どの程度早めに通知を受けるかを自由に設定できます。
> 
> ##### 今後さらに機能を追加予定です。
> 
> そして、これはまだ始まったばかりです。 Visual Studioは、Copilot を最大限に活用でき、利用状況をより明確に把握できるよう、継続的に改善を進めています。 今後のリリースでは、製品全体にわたってさらなるアップデートが予定されています。
> 
> ##### フィードバックをお寄せください
> 
> Copilot をよりスムーズに活用していただくために、ご意見をお聞かせいただければ幸いです。 フィードバックやご意見がありましたら、[Developer Community](https://developercommunity.visualstudio.com/) にお寄せください。  

**新しい Agent (プレビュー) をお試しください**

> _よりスマートで簡潔な Copilot エージェントに切り替えます。_
> 
> Visual Studio の Copilot Chat では、エージェントピッカーに新しい**エージェント (プレビュー)**オプションが追加されました。これは、GitHub Copilot CLI を動作させているのと同じ GitHub Copilot SDK を基盤としています。 エージェントは初回からより多くのタスクを正確に処理できるようになり、進捗管理のやり取りも減ります。また、返答も簡潔になり、一目で内容が把握しやすくなります。
> 
> **試す方法**
> 
> 1.  **GitHub Copilot Chat** を開く
> 2.  ウィンドウの下部にある**エージェント ピッカー**をクリックします
> 3.  **エージェント (プレビュー)** を選択します
> 
> ![Agent の下で Agent (Preview) が選択されている Copilot Chat のエージェント ピッカー](media/18.8/new-agent.png)
> 
> Visual Studio ですでに実施している作業: 機能の変更、バグ修正、リファクタリング、その他日々のタスクに活用してください。
> 
> この機能は現在プレビュー段階であるため、フィードバックをぜひお寄せください。 **問題を報告→フィードバックを送信→ヘルプを**通じて送信します。  

**Copilot で選択したコードを確認する**

> _選択した任意のコードに対するCopilotからのターゲット コード レビュー フィードバックを取得します_
> 
> 場合によっては、完全なコード レビューは必要ありません。特定のコード ブロックに関する 2 番目の意見です。 エディターでコードを選択し、右クリックして **Copilot アクション** → **Review Selection** を選択します。
> 
> Copilot は、選択した箇所に、レビューして対応できるインライン コメントを残します。 任意のコメントにあるスパークル アイコンを使ってコード提案を適用できます。提案がない場合は、Copilot に生成してもらうこともできます。
> 
> ![Copilot のアクションが表示され、[選択項目の確認] が強調表示されているコンテキスト メニュー](media/18.8/review-selection-context-menu.png)
> 
> これは、[GitHub Copilot コード レビュー](https://docs.github.com/en/copilot/how-tos/use-copilot-agents/request-a-code-review/use-code-review?tool=visualstudio)によって提供されます。コミットする前に **Git Changes** ウィンドウで変更を確認する場合と同じエクスペリエンスが得られます。  

**組織レベルのカスタム指示**

> _組織の所有者は、組織全体でCopilotの応答を調整するためのカスタム命令を追加できるようになりました_
> 
> **Note:** この機能を使用するには、リポジトリがGitHub組織に属している必要があります。
> 
> GitHub組織の所有者は、組織全体の特定のニーズや好みに合わせて応答を調整するために、Copilotのカスタム指示を追加できるようになりました。 これは、Copilotを使用するための基礎ルールを設定する必要があるチームや、チーム内のすべてのユーザーが恩恵を受けることができる一般的な指示を持っているチームに特に役立ちます。 これらの手順を設定する組織管理者については、「 [組織のカスタム手順を追加](https://docs.github.com/en/enterprise-cloud@latest/copilot/how-tos/copilot-on-github/customize-copilot/add-custom-instructions/add-organization-instructions#adding-organization-custom-instructions)する」を参照してください。 カスタム命令は設定を目的としており、ポリシーの適用には適していません。
> 
> 組織に属するリポジトリで作業している場合、組織レベルのカスタム手順が自動的に適用されます。 これらの手順は、Copilotの操作中に参照リストに表示され、リンクをクリックして完全な手順を表示できます。
> 
> ![参照リストに表示される組織レベルのカスタム命令](media/18.8/org-level-instructions.png)
> 
> 組織レベルの手順を使用しない場合や、ユーザー レベルの手順と競合する可能性を回避したい場合は、この機能を無効にすることができます。 **Tools → Options → GitHub → Copilot → Copilot Chat** に移動し、**組織レベルのカスタム命令**をオフにします。

### C++

**複数の VS インストール環境にまたがる MSVC Build Tools の自動検出**

> _Visual Studio は、現在のインストール内で最初に一致するプラットフォーム ツールセットで停止するのではなく、他のインストールからピン留めされたツールセットのバージョンを検索するようになりました。_
> 
> コンピューター上のすべての Visual Studio IDE および Visual Studio Build Tools インストールで MSVC Build Tools の自動検出を選択できるようになりました。これにより、ピン留めされた`VCToolsVersion`が別のインストールに存在する場合でも正しく解決されるようになります。
> 
> 以前は、Visual Studio は、現在のインストールに対象のプラットフォーム ツールセット用のツールセットが_まったくない_場合にのみ、他のインストールから一致するツールセットを検索していました。 たとえば、プロジェクトの対象が `v143` で、現在のVisual Studioに既に _any_`v143` ツールセットがインストールされている場合、個別のインストールにのみ存在する特定の `VCToolsVersion`を明示的に固定した場合でも、検索はそこで停止しました。
> 
> Visual Studioは、同じプラットフォーム ツールセットの別のバージョンが既にローカルに存在する場合でも、ピン留めした _exact_ バージョンを検索するために、引き続き他のインストールを検索します。
> 
> ##### 有効にする方法
> 
> `EnableVCToolsVersionDiscovery`をプロジェクトまたは`true`で`Directory.Build.props`に設定します:
> 
> ```
> <PropertyGroup>
>   <EnableVCToolsVersionDiscovery>true</EnableVCToolsVersionDiscovery>
>   <VCToolsVersion>14.43.34604</VCToolsVersion>
> </PropertyGroup>
> ```
> 
> ##### これが重要な理由
> 
> -   **バージョン ピンは実際に機能**します。現在のインストールに別のバージョンで同じプラットフォーム ツールセットが既に存在する場合でも、どのインストールに含まれているかに関係なく、指定された `VCToolsVersion` が適用されます。
> -   **ビルドの再現性**: 個々の IDE の更新によるコンパイラの動作の変更を気にすることなく、チーム全体で既知の優れたツールセット バージョンをピン留めします。
> -   **手動パスのオーバーライドなし**: クロスインストール ツールセット参照は、 `VCToolsInstallDir`を手動で配線する必要はなく、自動的に解決されます。  
>
