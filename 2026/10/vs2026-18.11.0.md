# Visual Studio 2026 バージョン 18.11.0 リリースノート

**2026年10月13日**にリリース。

### IDE

**段落番号付きドキュメント タブのショートカット 📣**

> _業界標準のキーボード ショートカットを使用して、ドキュメント のタブにすばやく移動できます。_
> 
> \+ テンキー1 から +テンキー9 を使って、開いているドキュメントにすばやく切り替えられるようになりました。 各ショートカットは、アクティブなドキュメント グループ内の対応する表示中のドキュメント タブをアクティブにするため、マウスを使わずにファイル間を素早く移動することができます。
> 
> ![番号付きタブ](media/18.11/numbered-tabs.png)
> 
> 番号付けは、固定されているタブと固定されていないタブの両方を含め、ドキュメントの表示順序に従っています。 プレビュー タブはショートカット スロットを消費しないため、番号付けが予測可能のままになります。 ショートカットはアクティブなドキュメント グループに限定されるため、グループを切り替えるとタブの割り当てが自動的に更新されます。
> 
> この動作により、Visual Studio は一般的なエディタの慣例に準拠するようになり、一貫した「キーボード優先」のワークフローを維持すると同時に、開発環境間の移行が容易になります。 これらのコマンドは、キーボードのカスタマイズやコマンド システムを通じて利用できます。
> 
> 📣 _フィードバックを共有し、会話を続けるには、[フィーチャーチケット](https://developercommunity.visualstudio.com/t/Numbered-Tab-Shortcuts-in-Document-Well/477176)をご覧ください_  

**\[フォルダーを開く\] では、復元設定が優先されます 📣**

> _\[フォルダーを開く\] では、ワークスペースの復元設定が優先されるようになりました。_
> 
> Visual Studio では、フォルダを再度開いた際に、開いていたドキュメントやソリューション エクスプローラーの状態を復元します。 以前は、_ソリューションの読み込み時にドキュメントを再開する_および_ソリューションの読み込み時にソリューション エクスプローラーのプロジェクト階層の状態を復元する_という設定は、ソリューション ベースのワークフローにのみ影響し、「フォルダを開く」の操作では、これらの設定に関係なくワークスペースが復元されていました。
> 
> 今回のアップデートにより、「フォルダを開く」機能でも、同じ設定が反映されるようになりました。 いずれかのオプションを無効にすると、Visual Studio はフォルダを再度開いた際に、開いているドキュメントやソリューション エクスプローラーの状態を復元しなくなります。
> 
> これらの基本設定を変更するには、\[**ツール\] → \[プロジェクトとソリューション→オプション\] → \[全般**\] に移動し、\[_ソリューションの読み込み時にドキュメントを再度開く\] と \[ソリューションの読み込み時__にプロジェクト階層の状態ソリューション エクスプローラー復元_する\] を構成します。 選択した動作は、ソリューションとフォルダの両方に一貫して適用されるようになりました。
> 
> 📣 _フィードバックを共有し、会話を続けるには、[フィーチャーチケット](https://developercommunity.visualstudio.com/t/Reopen-documents-and-Restore-SolExp-h/10999326)をご覧ください_  

**未保存の作業内容を失わない - Hot Exit 📣**

> _ホット終了では、未保存のファイルや未保存の変更がある保存済みファイルが保持されるため、中断したところから正確に再開できます。_
> 
> 有効にすると、Visual Studio を閉じるときに、Hot Exit によってセッションの状態が保存されます。 次回 Visual Studio を起動すると、開いていたドキュメント、編集内容、保存されていない変更内容が自動的に復元されるため、手動で保存する必要はありません。
> 
> Hot Exit を有効にするには、**ツール → オプション → プロジェクトとソリューション → 全般** に移動し、**ソリューションの読み込み時または空の環境で保存されていないドキュメントを再度開く** を選択します。
> 
> ![[プロジェクトとソリューション] > [全般] の設定。ソリューションの読み込み時または空の環境で [未保存のドキュメントを再度開く] が選択されている](media/18.11/hot-exit-settings.png)
> 
> Hot Exit で保持される内容:
> 
> -   保存されていないファイル。
> -   未保存の変更がある保存済みファイル。
> -   保存済みファイルでの元に戻す機能（Ctrl++Z を含む）。
> -   タブとウィンドウのレイアウト。
> 
> 📣 _フィードバックを共有し、会話を続けるには、[フィーチャーチケット](https://developercommunity.visualstudio.com/t/Add-ability-for-Visual-Studio-to-automat/10989739)をご覧ください_  

**フォントと色 📣**

> _統一された設定に基づいて構築された最新化されたフォントと色のエクスペリエンスを使用して、Visual Studioをカスタマイズします。_
> 
> 統一された設定に基づいて構築されたモダン化されたフォントと色のエクスペリエンスを使用して、Visual Studioをカスタマイズします。 以前は従来の \[ツール > オプション\] ダイアログから利用できた \[フォントと色\] では、Visual Studio 全体で使用されているものと同じ設定プラットフォームを利用するようになりました。
> 
> ![フォントと色の設定ページ](media/18.11/fontsandcolor.png)
> 
> 新しいエクスペリエンスでは、カテゴリベースのナビゲーション、統合検索、インライン プレビュー、および更新された色編集エクスペリエンスが導入されました。 前景色、背景色、フォント スタイル、プレビューは設定グリッド内に直接表示されるため、個々の項目を繰り返し選択することなく、既存のカスタマイズを確認したり、複数の設定を更新したりしやすくなります。
> 
> ##### settings.json に基づく
> 
> フォントと色の設定がVisual Studioの settings.json モデルに参加するようになりました。 UI を介して行われた変更は settings.jsonに反映されるため、上級ユーザーは両方のエクスペリエンスを同期したまま、ファイルを通じてカスタマイズを直接検査、編集、共有、または元に戻すことができます。
> 
> 📣 _フィードバックを共有し、会話を続けるには、[フィーチャーチケット](https://developercommunity.visualstudio.com/t/Add-a-search-box-in-Environment-Fonts/458349)をご覧ください_  

### 生産性

**ホバー ツールチップの遅延設定📣**

> _クイック情報ツールヒントが表示されるまでにコードにマウス ポインターを合わせておく時間を調整して、エディター内でマウスを動かしているときに邪魔にならないようにします。_
> 
> エディタ内のホバー ツールチップは、これまで常にホバーしてから 150 ミリ秒が経過すると表示されていました。 マウスをゆっくりと動かしたり、別の場所へ移動する途中でコードの上にカーソルを合わせたりすると、クリックしようとしていた行の真上にそのツールチップが表示されます。
> 
> ![クイック情報の遅延](media/18.11/quickinfo.png)
> 
> この遅延時間を設定できるようになりました。
> 
> **ツール → オプション → テキスト エディター → 詳細設定 → クイック情報のホバー遅延 (ミリ秒)**
> 
> デフォルトは 150 ミリ秒で、これは Visual Studio が従来から使用してきた値であるため、変更を加えない限り何も変わりません。 有効な値は 50 ～ 10000 ms です。 ツールチップが邪魔になる場合は表示レベルを上げ、表示を早めたい場合は下げてください。
> 
> この設定は直ちに適用されます。 再起動せず、ファイルも再開しません。
> 
> 適用範囲についての補足: これは、独自のタイミングを要求していないホバー ハンドラの遅延を制御するものであり、クイック インフォでもこれを使用しています。 明示的なホバー遅延を要求する拡張機能は、独自の動作を維持します。
> 
> 📣 _フィードバックを共有し、会話を続けるには、[フィーチャーチケット](https://developercommunity.visualstudio.com/t/Hover-Delay-Setting/780597)をご覧ください_  

**最初の障害時にビルドを停止する 📣**

> _残りのプロジェクトをビルドし続けるのではなく、最初の失敗後にビルドを停止Visual Studioできるようになりました。_
> 
> Visual Studio には、最初のプロジェクトでビルドに失敗した時点でソリューションのビルドを停止する、オプトイン設定が追加されました。 ビルドが正常に完了しなくなったプロジェクトを待機する必要がなく、より早くエラーの修正に取り掛かることができます。
> 
> \[**ツール\] → \[オプション\] → \[プロジェクトとソリューション\] → \[ビルドと実行**\] で**最初の失敗後**にソリューションビルドを停止します。 これを有効にすると、Visual Studio はキューに登録されているプロジェクトの起動を停止し、すでにビルド中のプロジェクトを安全に停止します。 ビルドは依然としてキャンセルではなく、失敗と報告されています。 この設定を無効のままにしておくと、ビルドの動作はこれまでと同じままになります。
> 
> ![フェールファストが有効で無効になっているビルド時間比較グラフ](media/18.11/fail-fast-chart.png)
> 
> 大規模なソリューションの場合、この改善効果は非常に大きいものとなる可能性があります。 テストの結果、この設定を無効にした場合の 4 回の通常ビルドの平均所要時間は 26 秒であったのに対し、有効にした場合は 1.5 秒となり、エラー発生後の完了までの時間が **94％ 短縮**されました。 結果はソリューションによって異なりますが、依存関係の連鎖が長いプロジェクトや、並列ビルドが多いプロジェクトほど、その効果を最も実感できる可能性が高いです。
> 
> 📣 _フィードバックを共有し、会話を続けるには、[フィーチャーチケット](https://developercommunity.visualstudio.com/t/Add-option-to-stop-projects-building-if/355793)をご覧ください_  

**キーボードを使用してドキュメントを移動する 📣**

> _ワークスペースの整理を容易にする新しいキーボード ショートカットを使用して、ドキュメント タブを再配置します。_
> 
> マウスを操作せずに、ドキュメント領域内のアクティブなタブの順序を変更できるようになりました。 Ctrl+Shift+PgUp はタブを 1 つのビジュアル位置左に移動し、Ctrl+Shift+PgDn はタブを 1 つの位置右に移動します。 縦型タブを有効にしている場合、同じショートカットでタブを上下に移動させることができるため、どのレイアウトを使用しても操作方法は変わりません。 これらのコマンドは、ドキュメントとドキュメント ウェル内に表示されているツール ウィンドウの両方で動作します。
> 
> タブの移動は、あらかじめ設定した構造に従って行われます。 固定されたタブと固定されていないタブは互いに分離された状態が保たれるため、タブがその境界を越えて移動し、固定セットが気付かないうちに崩れててしまうことがありません。 縦型タブでは、各タブは所属するプロジェクト グループ内に留まり、アルファベット順の並べ替えが有効になっている間は、手動での順序変更はできません。 プレビュー タブは移動できません。
> 
> ショートカットの背後には、 **Window.MoveTabLeft** と **Window.MoveTabRight** という 2 つの新しいグローバル コマンドがあり、別の場所にバインドする場合は、\[ **ツール\] → \[オプション\] → \[環境\] → キーボード** に表示されます。 デフォルト設定では、**Edit.ViewTopExtend** および **Edit.ViewBottomExtend** に対して、以前のテキストエディタのショートカット設定が引き継がれます。これらのコマンドは引き続き利用可能であり、好みのショートカットに再割り当てすることもできます。
> 
> Developer Community で投票してくださった皆様、ありがとうございました。 Ctrl+Shift+PgUp/PgDn は、ほとんどのブラウザーで使用されるバインディングと同じであるため、最初のプレスでは使い慣れていると感じるはずです。
> 
> 📣 _フィードバックを共有し、会話を続けるには、[フィーチャーチケット](https://developercommunity.visualstudio.com/t/Keyboard-shortcut-for-moving-tabs/1337230)をご覧ください_  

**ズーム キーボード ショートカットをリセットする 📣**

> _エディターを拡大または縮小した場合は、新しいキーボード ショートカットを使用してズーム レベルを 100% にリセットできるようになりました。_
> 
> Ctrl+NumPad0 キーを押して、エディターのズーム レベルを 100%にまっすぐ戻します。 コードが集約している部分を拡大して確認し、ズームアウトしてファイルの全体像を把握し、その後、キーを 1 回押すだけで通常の表示に戻すことができます。
> 
> これまでは、100% に戻すには、Ctrl+マウスホイールでズームをちょうどよさそうに見えるまで少しずつ調整するか、エディターの隅にあるズーム コントロールから値を選ぶ必要がありました。 ズームしすぎてしまう傾向もあり、特に感度の高いマウスホイールが、意図せずズームを変更してしまうと、とても厄介です。 この新しいショートカットを使えば、試行錯誤の必要がなくなり、ファイル間を移動しても編集画面の一貫性を保つことができます。
> 
> ショートカットは、新しい View.ZoomReset コマンドによってサポートされます。 Ctrl+NumPad0 は、VS Code とほとんどのブラウザーで使用されているバインドと一致しますが、他のものを使用する場合や、数値パッドのないキーボードを使用している場合は、\[**ツール\] → \[オプション\] → \[環境\] → キーボード**で再マップできます。
> 
> 📣 _フィードバックを共有し、会話を続けるには、[フィーチャーチケット](https://developercommunity.visualstudio.com/t/Reset-zoom-via-keyboard-shortcut/1373025)をご覧ください_  

**新しいマークダウン テンプレート 📣**

> _\[新しいファイル\] ダイアログから新しいマークダウン ファイルを作成できるようになりました。_
> 
> **新規ファイル**ダイアログから、直接マークダウン ファイルを作成できるようになりました。 Ctrl+Nキーを押し、Markdown を選択して、手動でファイルを作成したり、拡張子を設定したりせずに書き込みを開始します。
> 
> ![Markdown テンプレート](media/18.11/markdown-template.png)
> 
> このワークフローを使うことで、メモやドキュメント、その他のマークダウン コンテンツをより素早く作成できます。 また、Hot Exit とも連携しており、Visual Studio を再起動した際に未保存のファイルを復元するため、中断した箇所から作業を再開することができます。
> 
> 📣 _フィードバックを共有し、会話を続けるには、[フィーチャーチケット](https://developercommunity.visualstudio.com/t/Cannot-create-a-Markdown-file-by-New-Fi/10966564)をご覧ください_  

### GitHub Copilot

**新しいCopilot チャット エクスペリエンスを試す**

> _更新されたCopilot チャット。あらゆる場所でCopilotを強化するCopilot SDK 上に構築されています。_
> 
> Visual Studio には、Copilot CLI や GitHub Copilot アプリと同じ基盤である Copilot SDK を基に構築された、新しい Copilot Chat 機能が搭載されました。 これは、SDK を基盤として構築された初の Visual Studio エクスペリエンスであるエージェント (プレビュー) から始まったジャーニーの、次のステップです。 現在、この基盤が、「Ask モード」や「エージェント モード」、そして基盤となるチャット インフラスを含め、チャットのエクスペリエンス全体を支えています。
> 
> 共通の基盤を基盤とすることで、Copilot が進化すればするほど、Visual Studio もより良くなっていくことになります。 オンにすると、次が表示されます:
> 
> -   **より高度なエージェント ワークフロー**は、やり取りの往復を減らすと同時に、エンド ツー エンドのタスクを処理します。
> -   **セッションの継続時間を延長し**、プロンプトのキャッシュ機能を強化することで、パフォーマンスを向上させます。
> -   すべての Copilot インターフェースで**一貫した動作**。
> 
> ##### オンにする
> 
> 1.  Visual Studioで、\[**ツール\] →オプション**に移動します。
> 2.  **GitHub → Copilot → Copilot Chat**に移動します。
> 3.  **新しい Copilot Chat のエクスペリエンスの活用**を確認してください。
> 4.  Visual Studio を再起動して、変更を有効にします。
> 
> ![Visual Studioの新しいCopilot Chat エクスペリエンス](media/18.11/new-chat-experience.png)
> 
> そして、それをすでに行っている作業 (機能の変更、バグ修正、リファクタリング、その他あらゆる作業) に活用してください。
> 
> フィードバックをお待ちしております。 何かが見つからないか、機能していない場合は、 **ヘルプ→フィードバックを送信→問題を報告** して、次に優先順位を付ける必要があるかどうかを確認してください。

**コミットを作業ツリーと比較する 📣**

**マージ競合を一括で解決 📣**

> _1 ファイルずつ競合を解決する代わりに、すべてをまとめて保持するか取得できます。_
> 
> マージが何十ものファイルに及ぶと、競合を1ファイルずつ解決していくのはすぐにうんざりしてきます。
> 
> **Git の \[変更\]** で、\[結合**されていない変更**\] の下にあるファイル、フォルダー、またはリポジトリ ルートを右クリックし、\[すべて最新の状態に**保つ**\] または \[**すべての受信を受け取る**\] を選択して、その下のすべてを 1 つの手順で解決します。
> 
> ![Git の変更の [結合されていない変更] の下にあるフォルダーのコンテキスト メニューで、[すべての情報を最新の状態に保つ] オプションと [すべての受信を取る] オプションが表示されている](media/18.11/bulk-resolve-conflicts-menu.png)
