# Visual Studio 2026 バージョン 18.9.0 リリースノート

**2026 年 8 月 11 日**リリース。

### GitHub Copilot

**タスクに合わせてモデルの思考作業を調整する**

> _対応品質とトークン使用量のバランスを取るために、サポートされているモデルに対して低、中、高の思考力を選択します。_
> 
> モデルが問題をどれだけ推論するかを管理できるようになりました。 Visual Studio 18.9 は対応モデル向けに思考努力コントロールを追加し、タスクやトークン予算に応じて低/中/高の努力を選べます。
> 
> ##### 思考量の仕組み
> 
> 一部の Copilot モデルは現在、調整可能な思考レベルをサポートしています:
> 
> -   **低** - 推論を最小限に抑えて、素早く応答します。 率直な質問やコード提案に最適です。 トークンの使用量が少なくなります。
> -   **中** - 推論の深さと反応速度のバランス。 日常のコーディング作業に最適です。
> -   **高** - 複雑な問題に対する深層推論を使用します。 難しいアルゴリズム、アーキテクチャの決定、デバッグが難しい問題に最適です。 トークン消費量が多くなります。
> 
> **モデル ピッカー**や拡張された**モデル管理**ビューから直接思考量を調整できます。 低レベルはトークン予算内に収まりつつ、各タスクに役立つサポートを得られます。
> 
> ![低、中、高のオプションを含む思考作業ドロップダウンを示すモデル管理ビュー](media/18.9/manage-models-view.png)  

**Git エージェントで変更とコミットを確認する**

> _pull request の前に問題をキャッチします。_
> 
> pull request がコードに 2 番目の目を向けるのを待つ必要はありません。 作業中に変更またはコミットを確認するように **Git エージェント** に依頼します。
> 
> ##### コミットされていない変更を確認する
> 
> Copilot Chatで **Git エージェント**に切り替え、変更を確認するように依頼します。 エージェントは、コミットされていない作業を確認し、エディターでコメントをインラインで表示します。 **Git の \[変更\]** ビューにはナビゲート可能なリストが表示されるので、各コメントにすばやく移動できます。
> 
> \[**Git の変更**\] ウィンドウでCopilotレビュー アイコンを選択して、レビューを開始することもできます。
> 
> ![エディターのインライン レビュー コメントと、Copilot Chat パネルのファイルごとのコメント リスト](media/18.9/git-agent-changes-review-comment-2.png)
> 
> ##### コミットを確認する
> 
> コミットをコンテキストとしてCopilot Chatにアタッチし、**Git エージェント**に確認を依頼します。 レビュー コメントは、作業中のファイルとは別に、コミット固有のビューで変更されたファイルにインラインで表示されます。
> 
> コミット後に **Git Changes** 情報バーから直接コミット レビューを開始することも、 **Git リポジトリ** ウィンドウの任意のコミットから開始することもできます。
> 
> ![Copilot Chat パネルでファイルごとの結果を含むコミットのインライン レビュー コメント](media/18.9/git-agent-commit-review-comment-1.png)
> 
> Copilot Chatを使用してレビューを開始するときは、会話を続けて、結果を掘り下げ、説明を得るか、推奨される修正に取り組みます。 レビューは、GitHubリポジトリとAzure DevOpsリポジトリの両方で動作し、[GitHub Copilotコード レビュー サービス](https://docs.github.com/en/copilot/how-tos/use-copilot-agents/request-a-code-review/use-code-review?tool=visualstudio)を使用します。  

**組織レベルのカスタム エージェント**

> _GitHub組織の所有者は、組織全体にカスタム エージェントを追加できるようになりました。_
> 
> **注:** この機能は GitHub 組織が必要です。
> 
> カスタム エージェントを、組織内のリポジトリ間で共有できるようになりました。 GitHub 組織や企業オーナーは、組織内の全員が使えるカスタム エージェントを追加できます。 これによりチームの一貫性が保たれ、Copilot が組織のワークフローに整合し続けることができます。
> 
> 管理者の場合は、[「組織内でカスタム エージェントを使用する準備」](https://docs.github.com/en/copilot/how-tos/administer-copilot/manage-for-organization/prepare-for-custom-agents)または[「企業でカスタム エージェントを使用する準備」](https://docs.github.com/en/copilot/how-tos/administer-copilot/manage-for-enterprise/manage-agents/prepare-for-custom-agents#enabling-and-protecting-custom-agents-in-your-enterprise)を参照してください。
> 
> 組織内でリポジトリ作業をすると、Visual Studio は、組織レベルのカスタム エージェントを自動的に検出し、それをエージェント ピッカーで表示します。 エージェントにカーソルを合わせると、その説明と組織情報源が表示されます。 エージェント定義ファイルを表示するには定義ボタンをクリックします。
> 
> ![組織レベルのカスタム エージェント、説明、および定義ボタンを示すエージェント ピッカーのドロップダウン](media/18.9/org-level-agent.png)
> 
> チームのワークフローをサポートするために組織レベルのカスタム エージェントを設置しましょう。  

**Copilotの使用状況にアクセスする**

> _コンテキスト ウィンドウまたはバッジ メニューから、Copilotプランの使用状況に移動します。どちらが最適です。_
> 
> 作業を中断することなく、Copilot プランの利用状況を追跡できます。 Visual Studio 18.9 の \[コンテキスト\] ウィンドウから直接プランの使用状況を確認できます。
> 
> プロンプトボックス右上の **\[ドーナツ チャート\]** をクリックして、\[コンテキスト\] ウィンドウの使用状況を確認し、その後、プランの使用状況の詳細を開くボタンをクリックします。
> 
> ![[Copilot プロンプト] ボックスの [ドーナツ グラフ] アイコンでプランの使用状況の詳細を開く](media/18.9/copilot-usage-transparency.png)
> 
> \[使用状況\] ウィンドウと通知を改善し、より分かりやすく、必要な対応を取りやすくしました。 使用上限に近づいているタイミングや、使用を続けるためのオプションを確認できます。  

**モデル制御の向上**

> _お気に入りのモデルをピン留めし、残りの部分を折りたたんで、完全なモデルの詳細とカスタマイズ オプションを含む包括的な管理ビューにアクセスします。_
> 
> Visual Studio 18.9ではモデルの見つけ方や管理がより簡単になりました。 モデル ピッカーの再設計と新しい管理ビューにより、Copilot モデルの管理がより明確になります。
> 
> **改良型モデル ピッカー** - ピッカーはスキャンが速く、使いやすくなっています。 お気に入りのモデルをピン留めして、上部に表示されるようにし、普段使用しないモデルを折りたたむことで、画面をすっきりさせます。 最も重要なモデルに集中できます。
> 
> ![ピン コントロールと折りたたみコントロールを示すモデル ピッカー](media/18.9/model-picker-updated.png)
> 
> **モデル管理ビュー** - ピッカーで **\[モデルを管理\]** を選択すると、詳細とコントロールが完全に表示された展開ビューが開きます:
> 
> -   各モデルごとに、**コスト情報**、**機能**、**コンテキスト ウィンドウ サイズ**が表示されます。
> -   カスタム モデルとCopilot モデルを 1 か所でまとめて管理できます。
> 
> ![モデルの詳細とコントロールを示すモデル管理ビュー](media/18.9/manage-models-view.png)  

### Git ツール

**複数ファイルの概要の相違 📣**

> _統合形式の差分でファイル変更を表示し、迅速に理解できます。_
> 
> 複数ファイル概要の差分では、複数のファイルから取得したすべての変更済みの行が 1 つの統合ビューの中で表示されるので、複数ファイルの間を移動せずに、コミットまたは pull request (プル リクエスト) のスコープをすばやく把握できます。
> 
> ![複数のファイルから変更された行を表示する統合パネル](media/18.9/multi-file-summary-diff-collapsed-2.png)
> 
> **\[Open changes summary (変更の概要を開く)**\] ボタンが、次のように複数の場所に表示されます:
> 
> -   **Git の変更**
> -   **Git → View Branch History** の**コミットの詳細**
> -   **\[Git リポジトリ→表示**\] ウィンドウで**要求をプル**する
> 
> 現在、pull request (プル リクエスト) の一覧は、プレビュー機能 _\[View pull requests for a Git repository (Git リポジトリを対象とするプル リクエストの表示)\]_ を使用している Visual Studio Insiders でのみ使用できます。
> 
> ![Git 変更ツール バーの [変更の概要] ボタンを開く](media/18.9/multi-file-summary-diff-git-changes-button.png)
> 
> 📣 _フィードバックを共有し、会話を続けるには、[フィーチャーチケット](https://developercommunity.visualstudio.com/t/Add-overview-of-all-changed-lines-to-the/10582310)をご覧ください_  

**Git サブモジュールのサポート 📣**

> _統合された追加、更新、削除、ナビゲーションのサポートを使用して、Visual Studioで Git サブモジュールを直接管理します。_
> 
> 最も要望の多い Git 機能の一つである一流のサブモジュール サポートが Visual Studio 18.9 で利用可能となり、IDE を離れずにサブモジュールを管理できます。
> 
> サブモジュールは Git エクスペリエンスに完全に統合されています。 ご契約特典:
> 
> -   Git リポジトリ ウィンドウ内の専用サブモジュールセクション。
> -   Git の変更による可視性の向上。
> -   ブランチおよびリポジトリ ピッカーが親子リポジトリの階層を表示します。
> 
> ![[Submodules]\(サブモジュール\) セクションが表示されている Git リポジトリ ウィンドウ](media/18.9/git-submodule-support-repo.png)
> 
> \[サブモジュール\] セクションで、サブモジュールの追加、更新、削除が可能です。 Visual Studio はソリューションやフォルダを開く際に自動的にサブモジュールを検出して有効化し、ローカル リポジトリ リストから除外して雑多さを減らします。
> 
> ![親階層とサブモジュール階層を示すリポジトリ ピッカー](media/18.9/git-submodule-support-select-repo.png)
> 
> 既定では、サブモジュールは読み取り専用です。 サブモジュールを使用するのではなく、サブモジュール内で作業する場合は、\[ **Tools → Options → Source Control → Git** に移動し、\[ **複数のリポジトリを自動的にアクティブ化する**\] を見つけて、\[ **はい\]、\[サブモジュールを含める**\] の順に選択します。
> 
> これは進化し続けるエクスペリエンスの最初のマイルストーンであり、今後のリリースでさらに改善が予定されています。
> 
> 📣 _フィードバックを共有し、会話を続けるには、[フィーチャーチケット](https://developercommunity.visualstudio.com/t/full-git-submodule-support/351549)をご覧ください_  

**ワークツリー: 一度に複数のブランチで作業する 📣**

> _Git ワークツリーを作成、開いて管理することで、stash や再クローンを行うことなく、複数のブランチで同時に作業できます。_
> 
> 別の分岐を確認するために中途半端な作業をいったん退避したことがあるなら、ワークツリーを使えばその手間を省けます。 各ワークツリーは同じリポジトリ用の個別の作業ディレクトリであるため、進行中の作業は他の場所で作業している間も変更されません。
> 
> **\[Git リポジトリ\]**ウィンドウで任意の分岐を右クリックし、**\[新しいワークツリーから\]** を選択してワークツリーを作成します。 新しい分岐から始めるか、選択した分岐を使うことができます。 履歴グラフ内の任意のコミットからワークツリーを作成することもできます。 現在のウィンドウや新しい Visual Studio インスタンスで開いて、両方の分岐を並行して操作してください。
> 
> ![［〜から新しいワークツリー］、［現在のウィンドウでワークツリーを開く］、［新しいウィンドウでワークツリーを開く］、［ワークツリーを削除］の各オプションが表示されたブランチのコンテキストメニュー](media/18.9/git-worktrees-context-menu.png)
> 
> ワークツリーは、ブランチと共にインラインで表示されます。 分岐リスト、分岐ピッカー、リポジトリ ピッカーから切り替えることができます。 作業が終わったら、ワークツリーを右クリックして **\[作業ツリーを削除\]** を選択して整理してください。
> 
> ![ブランチと並んでワークツリーが表示された Git リポジトリのブランチ一覧](media/18.9/git-worktrees-branch-list.png)
> 
> 📣 _フィードバックを共有し、会話を続けるには、[フィーチャーチケット](https://developercommunity.visualstudio.com/t/Git-worktree-support-in-the-Visual-Studi/10708556)をご覧ください_  

**Copilotを使用してコミットを確認する**

> _コミットに関するプライベート Copilot コード レビューを取得します。_
> 
> Copilot のコード レビューでは、コミットされていない変更に対してすでにフィードバックを提供します。 コミットされた変更に対して同じレビューを実行できるようになりました。
> 
> **\[Git リポジトリ**\] ウィンドウでコミットを右クリックし、\[**コミットの確認**\] を選択してそのコミットを確認します。 2 つのコミットを選択して、それらの間で変更された内容をすべて確認します。
> 
> ![Git リポジトリ ウィンドウの [コミットの確認] オプションを示す右クリック コンテキスト メニュー](media/18.9/copilot-commit-review-context-menu.png)
> 
> Copilot Chatでコミットを参照し、**Git エージェント**に確認を依頼することもできます。
> 
> ![特定のコミットの確認を求める Git エージェント プロンプトが表示されたCopilot Chat ウィンドウ](media/18.9/copilot-commit-review-git-agent.png)
> 
> Copilotのレビュー コメントは、変更されたファイルにインラインで表示されます。 \[ **コミットの詳細\]** ウィンドウに 1 つのコミットが開きます。 2 つのコミット間の範囲が **Compare Commits** ビューで表示されます。 任意のコメントを選択して、そのコードに直接ジャンプします。
> 
> ![[コミットの詳細] ウィンドウに表示されるインライン Copilot レビュー コメント](media/18.9/copilot-commit-review-comments.png)
> 
> レビューは、Visual Studio セッションに対してローカルに維持され、GitHubリポジトリとAzure DevOpsリポジトリの両方で動作します。
> 
> この機能を有効にするには、\[**Tools → Options → GitHub → Copilot → Source Control Integration** に移動し、\[Git の変更をローカルで確認する\] をオンに**して、コメントからの提案を提供します**。  

**ファイルと作業ツリーを比較する 📣**

> _ファイルの以前のバージョンと現在のローカル変更を比較します。_
> 
> 以前のコミット以降にファイルがどのように変更されたかを確認したいですか? これで、任意のファイル バージョンを現在の作業ツリーと比較できるようになりました。
> 
> **ソリューション エクスプローラー**でファイルを右クリックし、**Git → \[履歴の表示\]** を選択します。 次に、ファイル履歴でコミットを右クリックし、\[ **作業ツリーと比較**\] を選択します。
> 
> ![作業ツリーとの比較を示すファイル履歴のコンテキスト メニュー](media/18.9/compare-working-tree-history-menu.png)
> 
> Visual Studio、左側にコミット バージョン、右側に作業ツリーのバージョンとの差分が開きます。 コミットされた編集やコミットされていない編集を含め、そのコミット以降のすべての変更を確認できます。
> 
> ![コミットされたファイルバージョンが左側に表示され、作業ツリーのバージョンが右側に表示されている差分ビュー](media/18.9/compare-working-tree-diff.png)
> 
> 📣 _フィードバックを共有し、会話を続けるには、[フィーチャーチケット](https://developercommunity.visualstudio.com/content/idea/370956/allow-compare-working-copy-to-historical-version-v.html)をご覧ください_  

**PR レビューの更新 - オートコンプリートとタイムライン 📣**

> _pull request を自動的に完了するように設定し、その更新履歴をVisual Studioで確認します。_
> 
> 引き続き、Visual Studioの pull request エクスペリエンスが向上しています。
> 
> ![オートコンプリートと更新タイムラインVisual Studio表示されている pull request ビューの [概要] タブ](media/18.9/pr-review-updates-autocomplete-timeline.png)
> 
> -   **オートコンプリート/自動マージ**: 必要な承認とポリシー チェックを満たした後に、pull request を自動的に完了するように設定します。
> -   **タイムラインの更新**: プッシュ、投票、その他のイベントのプル要求履歴を **\[概要** \] タブに表示します。
> 
> これらの更新は、GitHubリポジトリとAzure DevOpsリポジトリで動作します。
> 
> 📣 _フィードバックを共有し、会話を続けるには、[フィーチャーチケット](https://developercommunity.visualstudio.com/t/VS2022-171-Git-Pull-Request-is-gone/1576559)をご覧ください_
